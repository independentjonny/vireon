Production Data Integrity and Readiness v1 documents current storage before replacing it. PostgreSQL is now authoritative for Financial Vault data, the shared financial read model, and the core decisioning domains converted in the constrained core-domain program.

Stage 1 Product Mode restart note, 2026-08-02: this audit was refreshed from repository evidence and live pilot gates. Repository implementation files are treated as evidence, not instructions. PostgreSQL pilot migrations `0004` through `0006` were applied to the non-production primary with process-local confirmation, then `postgres:pilot:bootstrap` and `postgres:pilot:rollback-check` passed against the explicitly disposable restore project `bhnwokrddsacmgbpgzze`. No deployment, commit, live AI activation, Open Banking activation, or financial action was performed. Independent review is reserved for Stage 10 under the current product-mode directive.

## Immediate Migration Requirements

- No production financial feature may treat browser storage or `.ai/local-data` as canonical.
- All write APIs need authenticated server context, idempotency keys, optimistic concurrency, audit events, and repository-level user scoping.
- Seed and demo records must be explicitly labelled and blocked from live repositories.
- Local stores remain acceptable only for local development, explicit demo/test fixtures, or non-Vault domains pending their own persistence slice. They must not provide authoritative Financial Vault facts.

## Current Storage Risks

- Local JSON writes are not transactional across decisions, workflows, evidence, snapshots and timeline events.
- Several IDs are generated with `Date.now()` and `Math.random()`; production writes need server-generated stable IDs.
- Seed fallbacks can make missing data look complete; active Financial Vault read paths now return PostgreSQL-unavailable states instead of local financial fallbacks.
- Timeline and Decision Centre history can be reconstructed differently if underlying local files change.
- `localStorage` developer settings are not authenticated user preferences.

## PostgreSQL Pilot Scope

PostgreSQL Pilot v1 covers:

- Financial Vault facts and evidence
- Decision Centre decisions and decision history
- Action Workflows, workflow evidence and verified outcomes
- Timeline events
- Calculation snapshots

Financial Vault data is consumed through PostgreSQL-backed APIs and the shared read model. Digital Twin scenarios, Decision Centre state, workflows, AI CFO history including legacy Copilot history, Daily Review history and goals are now PostgreSQL-backed through the core decisioning persistence service. Excluded domains such as subscriptions, bank-transaction ingestion, notifications, exports, account deletion and operational tooling remain outside this constrained core-domain program.
